# CourseShop

Навчальний вебзастосунок для перегляду та купівлі онлайн-курсів. Студент може зареєструватися, увійти, купувати курси й переглядати їх у профілі. Користувач із роллю `admin` може додавати курси через панель викладача.

## Технології

- React 19, TypeScript, Vite
- React Router — маршрутизація
- Redux Toolkit — стан авторизації
- TanStack Query — завантаження та кешування даних
- Axios — HTTP-запити
- React Hook Form і Zod — форми та валідація
- JSON Server — локальний mock REST API

## Вимоги

- Node.js та npm

## Запуск локально

Відкрийте термінал у папці `CourseShopFinalProject` і встановіть залежності:

```bash
npm install
```

Запустіть mock API в першому терміналі:

```bash
npx json-server --watch db.json --port 3001
```

Запустіть frontend в іншому терміналі, також із папки проекту:

```bash
npm run dev
```

Відкрийте адресу, яку покаже Vite (зазвичай `http://localhost:5173`). API доступне на `http://localhost:3001`.

Frontend використовує `http://localhost:3001` за замовчуванням. Щоб вказати іншу адресу API, створіть `.env.local` у корені проекту:

```dotenv
VITE_API_URL=http://localhost:3001
```

## Як увійти як адміністратор

У початковому `db.json` немає користувача з роллю `admin`. Реєстрація через форму створює лише користувачів із роллю `student`, тому створити admin через UI не можна. На даний момент можна добавити до db.json аккаунт адміна.

3. Перейдіть на `/login` (наприклад, `http://localhost:5173/login`) і введіть `admin@example.com` та пароль, який щойно вказали.
4. Після входу відкрийте пункт **«Додати курс»** у шапці або перейдіть на `/admin`.

JSON Server збереже цього користувача у локальному `db.json`. Для повторного запуску API створювати користувача повторно не потрібно. Щоб видалити тестовий обліковий запис, зупиніть API та приберіть відповідний об'єкт із масиву `users` у `db.json`.

> **Важливо:** це лише локальна навчальна авторизація. Паролі зберігаються у `db.json` відкритим текстом, токен є фіктивним, а перевірка ролі виконується тільки у frontend. JSON Server не захищає API і не повинен використовуватися для реальних користувачів чи production-застосунку.

## Основні можливості

- Перегляд каталогу курсів.
- Реєстрація та вхід; форми перевіряються схемами Zod.
- Купівля курсу для авторизованого користувача та перегляд придбаних курсів у профілі.
- Admin-панель для додавання курсів і перегляду каталогу.
- Збереження стану входу у `localStorage`.

## Структура `src`

```text
src/
├── app/
│   ├── App.tsx                 # маршрути, спільні Header і Footer
│   ├── store.ts                # Redux store та збереження авторизації
│   └── layout/                 # шапка та підвал
├── features/
│   ├── auth/                   # вхід, реєстрація, роль і захищені маршрути
│   ├── admin/                  # панель додавання курсів
│   ├── courses/                # каталог, картка курсу та API-запити
│   ├── profile/                # профіль і список придбаних курсів
│   └── purchases/              # купівлі та відповідні API-запити
├── entities/                   # базові типи User, Course і Purchase
├── shared/api/                 # конфігурація Axios та адреси API
├── assets/                     # статичні ресурси
├── main.tsx                    # точки підключення React, Router і провайдерів
├── App.css                     # стилі компонентів застосунку
└── index.css                   # глобальні стилі
```

Дані зберігаються у `db.json`: `courses`, `users` і `purchases`. Основні API-маршрути: `/courses`, `/users`, `/purchases`.

### Потік авторизації

`LoginPage` передає email і пароль у `authApi`, який шукає відповідний запис у `/users`. Дані користувача потрапляють у Redux через `authSlice`; `store.ts` зберігає їх у `localStorage`. `ProtectedRoute` вимагає авторизацію для `/profile` і роль `admin` для `/admin`. Нові реєстрації завжди отримують роль `student`.
